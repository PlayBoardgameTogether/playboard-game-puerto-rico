# 海港棋桌 1.1.0 交付验证（2026-10-25）

本批把入口徽章、港湾主题和实体物件画面纳入实际棋桌，并增加直接选船、装载预览、物件详情及投影事件动画。经典基础规则不变，游戏/资源版本 1.0.0 → 1.1.0，contentVersion 保持 1.0.0，SDK `^0.1.0`、ZIP v1。旧局与旧包不可覆盖。

## 实际执行

| 命令 / 范围 | 结果 |
| --- | --- |
| `pnpm test` | 16/16；包括 3、4、5 人完整脚本对局、每步恢复与权限/私密 View 断言 |
| `pnpm build` | 三文件安装 ZIP；内嵌 PNG，仍低于 2 MiB 解压预算 |
| `pnpm verify` | 1/1；真实平台解析器与 QuickJS 验证最小/最大人数、本人视图、动作与恢复，准备 SHA256SUMS 和 release.json |
| `pnpm test:ui --output=test-results/final` | 四视口 8/8；1440×900、1280×800、390×844、320×740，亮暗画面、键盘、工人、详情、提交保护和动画去重；后续调整仅手机确认定位 |
| `pnpm test:ui --project=mobile --project=small-mobile --output=test-results/mobile-final` | 最终手机原位确认方案 4/4，选船预览不发送动作、确认只发送一次；减少动态和只读回放不播放动作动画 |

平台侧通过其原 `test:e2e` 准备脚本使用独立测试库验证，未用浏览器固定场景冒充联机。桌面实际安装、三人准备、工人行动、隐私和刷新恢复通过；手机初轮发现固定确认栏与平台导航重叠，修复为船旁/岗位确认后，最终手机 sandbox 与三账号用例 **2/2 通过**。平台命令通过 `PUERTO_RICO_TEST_VERSION=1.1.0` 指向本次包；平台的源码锁仍保持已发布 1.0.0，本轮不直接修改平台游戏副本。

最初平台固定场景有动作回调未结束就替换全局 state 的竞态，准备流程有未等待席位同步的问题；在平台测试内补齐结果等待，未修改规则、降低断言或放宽隔离。一次新测试库媒体准备失败，保留原校验；同版本不同构建的测试目录也被安装器正确拒绝覆盖。最终在新的独立库通过原完整准备流程完成手机联机验收。

图稿、原图和生成提示词见 `design/` 与 `game-packages/puerto-rico/art/README.md`。实际截图在本地忽略目录 `test-results/final/`、`test-results/mobile-final/`，平台截图随独立交付目录提供；不提交含测试会话的 trace、数据库或生成 ZIP。

打包最后统一文本行尾与 ZIP 本地日期字段，`TZ=UTC` 与 `TZ=Asia/Shanghai` 两次构建摘要相同，最终 `pnpm verify` 再通过。该调整只影响跨系统归档一致性，不改变已验证的画面与动作行为。

## 限制与发布状态

- 用户明确本次先交付安装包：不合并发布、不打标签、不创建 GitHub Release、不上传生产、不更新服务器或平台来源锁。
- 管理员仍须通过原检查与审核流程安装 1.1.0；GitHub 源码 ZIP 不能安装。平台的 Logo 容器/详情横幅通用修补在平台独立 PR，安装游戏包本身不会改写平台 CSS。
- 浏览器采用 Chromium 及设备仿真，未验证物理手机、软键盘、Safari、真实模型供应商或真人整局；脚本整局不能替代这些验证。没有新增音效或教程。
